Автоматизации: было → стало

Двенадцать реальных кейсов. По каждому честно: что было, как работает сейчас, чем проверено и в каком статусе. Пилот - это пилот, не готовый продукт.

1. Входящие документы из ЭДО → проведение в 1С

Было: Каждый документ открывать, сверять даты, суммы, НДС, дубли, договор и счёт; очередь копится
Стало: Скрипт читает всю очередь входящих, сверяет с договором, счётом и средними суммами, проводит типовые, а аномалии (например, сумма в 1000 раз выше средней) помечает сигналом и откладывает
Технологии: 1С OData, веб-клиент 1С, Python
Статус: Рабочий прототип: очередь читается целиком, прогон без записи (dry-run), 29 тестов. Боевое проведение включается после согласования правил

2. Акты сверки из ЭДО → акт в 1С

Было: Акт приходит PDF-ом из ЭДО, бухгалтер вручную переносит данные контрагента
Стало: Цикл целиком: акт из ЭДО → наш акт в 1С через OData → данные контрагента из PDF с проверкой арифметики → проведение → привязка к документу
Технологии: 1С OData, pdfplumber, Python
Статус: Боевой цикл. Проведено 2 боевых акта (17.09.2026)

3. Оплата поставщикам, налогам, ЕНП, дивидендам

Было: Платёжки набираются руками, выгрузка в банк - отдельная возня
Стало: Счёт → платёжное поручение в 1С → файл для интернет-банка (txt) → отметка статуса. Подпись и оплата - только у ответственного
Технологии: 1С OData, выгрузка в клиент-банк
Статус: Рабочий. Платёж не уходит без подписи человека

4. Реализации, акты, УПД, парные счета-фактуры

Было: Типовые документы по десяткам договоров, ошибки с датами и номерами, договор без даты
Стало: Создание и восстановление реализаций и актов пакетом, парная счёт-фактура, правила для договоров без даты и номера
Технологии: 1С OData, скрипты правил
Статус: Правила и скрипты отработаны, включая договоры без даты и номера

5. Закрытие месяца

Было: Чек-лист в голове, часть шагов забывается
Стало: Регламентные операции в нужном порядке, календарь закрытия с датами и статусами (см. вкладку «Календарь закрытия»)
Технологии: 1С + Google Таблицы
Статус: Рабочий чек-лист и таблица статусов

6. Ведомости ЗУП через веб-клиент

Было: Нет прямого доступа к базе, ручной ввод ведомостей
Стало: Заполнение и проверка ведомостей через веб-клиент 1С в фоне, без ввода руками
Технологии: Playwright, 1С веб-клиент
Статус: Рабочий способ там, где OData недоступен

7. Агентская схема с франчайзи

Было: Сверять отчёты агента с данными CRM вручную, споры по расчётам
Стало: Методика, регламент и инструкция бухгалтеру (docx/pdf/html), сверка отчёта агента с CRM по схеме
Технологии: Python, Excel, CRM
Статус: Прогон на копии базы за июнь 2026, схема в файле

8. Управленческая отчётность: БДР, БДДС, баланс

Было: Выгрузки из 1С в Excel, собирать вручную каждый месяц
Стало: OData → SQLite → Power BI и Google Таблицы: БДР, ДДС, баланс, ликвидность, затраты. Сходимость проверяется при сборке
Технологии: 1С OData, SQLite, Power BI, Google Таблицы
Статус: Проверено живым открытием: 114 568 проводок и 74 751 документ банка и кассы за 2020-2026. Баланс укрупнённый

9. Сверка выручки сети моек

Было: Заказ, оплата, чек ОФД, эквайринг, выплата банка, расчётный счёт и 1С сверялись в хрупком Power Query
Стало: Единая цепочка: заказ → оплата → чек ОФД → эквайринг/СБП → выплата банка → р/с → 1С, расхождения видны сразу
Технологии: Python, SQLite, ОФД, эквайринг
Статус: Пилот (MVP), не готовый продукт

10. Контроль договоров в 1С

Было: Договор в документе не совпадает с назначением платежа, номера теряются, нет контроля сроков
Стало: Обработка проверяет документы по договору: статусы «привязать», «расхождение», «совпало», фильтры, сортировка, переход в документ двойным кликом
Технологии: Внешний отчёт .epf, 1С 8.3
Статус: Опубликовано на Инфостарте, приёмка на копиях баз

11. Комиссия эквайринга под счёт-фактуру

Было: Комиссию банка раскладывали вручную по эквайринговым отчётам
Стало: Расчёт и отражение комиссии под счёт-фактуру, живая приёмка на 8.3 и 8.5
Технологии: Внешняя обработка .epf
Статус: 31 проверка пройдена на 8.3 и 8.5, на модерации Инфостарта

12. Заполнение контрагентов по ИНН пачкой

Было: Карточки контрагентов правили по одной, написание названий разное
Стало: Пачкой по ИНН: показывает «было → станет» до записи, отмена в 1 клик
Технологии: Внешняя обработка .epf
Статус: Скриншоты на 8.3 и 8.5, на модерации Инфостарта

Как я делаю автоматизацию

  1. Разведка: смотрю, как работает процесс и где теряется время.
  2. Техзадание в пять абзацев и согласование до начала работы.
  3. Разработка на копии базы.
  4. Автоприёмка: набор проверок на нескольких версиях платформы.
  5. Первый запуск без записи, отчёт «что изменится».
  6. Деньги, подписи и отправка документов только явным действием человека.
